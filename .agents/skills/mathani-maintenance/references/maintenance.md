# مرجع الصيانة الفنية لمثاني

يُقرأ القسم الذي تحتاجه المهمة فقط. جذر المشروع هو المجلد الذي يحتوي pubspec.yaml باسم mathani. الإحالات التالية نسبية إلى ذلك الجذر.

## مصادر الحقيقة

- بيئة Flutter: .fvmrc، وحدود SDK والتبعيات: pubspec.yaml؛ النسخ المحلولة: pubspec.lock.
- Android: android/settings.gradle.kts وملفا build.gradle.kts وandroid/gradle.properties وGradle wrapper.
- متطلبات الشكل والسلوك: طلب المستخدم الأحدث ثم DESIGN_SYSTEM.md ووثيقة المكوّن المعني. تقارير التحديث القديمة سجل تاريخي، لا بديل عن ملفات الضبط الحالية.
- قواعد التفويض والتجميد وحفظ العمل: AGENTS.md.

## الواجهات والترجمة

- يستخدم المشروع material_ui وcupertino_ui المستقلتين. لا تُدخل استيرادات Material/Cupertino القديمة بسبب مثال من مكتبة أو قالب أقدم.
- إذا كانت المهمة تحتاج flutter pub get أو تعدّل ARB، شغّل `dart run scripts/generate_localizations.dart` بعدها. قد يعيد مولّد Flutter العادي مندوبات ترجمة قديمة؛ السكربت يعالج الاستيرادات المولدة فقط دون ترقيع SDK.
- افحص RTL والثيمات وتكبير النص ومساحة المحتوى الفعلية حيث يمسها التعديل. لا تعمم إعادة التصميم على بقية الصفحات.
- افصل بين مساحة Flutter والأشرطة التي يديرها النظام. عند تغيير سياسة النظام راجع Flutter وAndroid معًا؛ النسخ المستهدفة الحديثة قد تتجاهل أوضاع SystemChrome القديمة.
- موضع تكامل النظام الحالي: lib/core/services/reader_system_ui.dart وandroid/app/src/main/kotlin/com/example/mathani/MainActivity.kt. متطلبات ظهوره في وثيقة التصميم، وليست سياسة لجميع الشاشات.
- اختبارات Widget والقناة الوهمية تثبت التخطيط والطلبات المرسلة، لا التنفيذ البصري على الهاتف. لا تقل إن 60/120fps أو الهوامش على الجهاز تحققت دون قياس أو مشاهدة فعلية.

## التبعيات وأدوات البناء

- عندما تكون الترقية مصرحًا بها، حدّد الإصدار الحالي والمستهدف وقيود SDK والتغييرات الكاسرة. لا تستخدم pub upgrade --major-versions للمشروع كله كاختصار.
- راجع التغييرات غير المباشرة في pubspec.lock، خصوصًا التسجيل والتسميع والمكتبات الأصلية المجمدة. لا ترفع قيدًا أو تضف dependency_overrides لإجبار محلّل التبعيات على النجاح.
- حزم Isar Community للمحرك والمكتبات الأصلية والمولّد مثبتة ومتوافقة مع build_runner محدد. المرجع هو القيود الفعلية، لا رقم «الأحدث».
- بعض ترقيات الإضافات ترفع compileSdk أو متطلبات Java/Kotlin/AGP. تحقّق من سجل الحزمة الرسمي قبل اقتراح تغيير SDK. لا تعدّل Pub cache أو Flutter SDK لإخفاء عدم توافق المشروع.
- التوافق الحالي يتضمن إعدادات Kotlin/DSL ودعم wakelock في Gradle. لا تحذفها أثناء تنظيف غير متعلق، ولا تزعم توافق كل الإضافات من نجاح gradlew help.
- ذاكرة تنزيل التبعيات تختلف عن ذاكرة نتائج المهام وعن configuration cache. لا تمسح الكاش روتينيًا؛ شخّص التنزيل أو الحالة التزايدية أو خطأ المصدر أولًا. لا تعد بزمن بناء غير مقاس.

## البيانات والتوليد

- ولّد .g.dart من المصدر عند الحاجة المصرح بها بواسطة `dart run build_runner build`، ثم راجع الفروق. لا تغيّر المخطط أو المعرّفات لحل مشكلة مولّد عابرة.
- راجع lib/core/database/isar_service.dart: يحفظ نسخة قبل الترحيل ولا يحذف قاعدة غير قابلة للفتح. لا تستبدل هذا السلوك بإعادة ضبط تلقائية.
- test/fixtures/isar_v3/ مرجع اصطناعي ثابت منشأ بالمحرك القديم، وليس بيانات مستخدم. لا تعِد توليده بمحرك جديد ولا تفتحه في مكانه للكتابة؛ الاختبار ينسخه إلى مجلد مؤقت.
- اختر test/unit/database/isar_migration_test.dart عند لمس التوافق. نجاحه على مكتبة سطح المكتب لا يثبت ترقية كل قاعدة Android حقيقية.

## التحقق

اختر فحوصًا تتناسب مع التغيير. أمثلة لا تُنتج APK:

```text
git diff --check
dart format --output=none --set-exit-if-changed <ملفات Dart المتأثرة>
flutter analyze --no-pub
flutter test --no-pub <مسار الاختبار المناسب>
```

شغّل التهيئة أو التوليد فقط إذا احتاجهما الطلب؛ تجنّب إعادة التنسيق أو التوليد الشاملين دون داعٍ. إذا تعذر غلاف Flutter بسبب البيئة، استخدم SDK المضبوط أو اشرح العائق؛ لا تعدّل تثبيت SDK بوصفه إصلاحًا ضمنيًا للتطبيق.

اختر من الاختبارات الموجودة بحسب المسار:

- Material والترجمة: test/widget/material_migration_test.dart.
- القراءة والتقليب والحدود: reader_ui_test.dart وreader_page_bounds_test.dart تحت test/widget/، وسياسة النظام في test/unit/services/reader_system_ui_test.dart.
- تنزيل المصحف والأرشيف: test/unit/services/mushaf_downloader_upgrade_test.dart.
- الصوت: test/unit/providers/audio_provider_test.dart واختبارات إمكانية الوصول ذات الصلة.

للاختبارات آثار محلية: مجلدات مؤقتة، وخادم loopback للأرشيف، وتحميل Isar أصلية لسطح المكتب. لا تستخدم بيانات الهاتف ولا تستدعِ main أو خدمات حقيقية لمجرد اختبار Widget؛ بدء التطبيق يهيئ خدمات أصلية منها التسميع.

آخر خط أساس موثّق بعد تحديث المكتبات: 17 ملاحظة أسلوبية في ملفات التسميع المجمدة دون أخطاء أو تحذيرات. اقرأ النتيجة الحالية ولا تفترض استمرار الرقم؛ flutter analyze يعيد فشلًا مع الملاحظات. لا تُخفِ القواعد ولا تفك التجميد لتصفير النتيجة.

## الإصدار والأجهزة وGitHub

هذا القسم لا يُنفّذ دون تفويض يشمل الفعل. طلب إصلاح أو شرح أو رفع مصادر لا يجيز APK. flutter run وسكربت profile وبعض مهام Gradle قد تبني أو تثبت التطبيق؛ اسم «اختبار» ليس ضمانًا لخلو الأمر من ذلك. افحص task graph إذا احتجت تحققًا أصليًا دون APK، وأبقِ AOT والتغليف والتثبيت خارج النطاق غير المصرح به.

عند طلب البناء صراحة:

- اقرأ scripts/build_android_release.ps1 والتوقيع الحالي قبل تشغيله؛ لا تبدّل مفتاح التوقيع أو applicationId.
- يُحفظ ملف APK الناتج في مسار المخرجات الافتراضي (`build/app/outputs/flutter-apk/` مع الأرشفة في `artifacts/apk/`)، ويُمنع منعاً باتاً حفظ ملفات APK في المجلد الجذري للمشروع للحفاظ على نظافة الجذر. يحفظ السكربت الناتج السابق في الأرشيف، ويستهدف arm64، ويرفض استبدال ملف مؤرشف باسم الإصدار نفسه. طلب APK جديد يجيز أقل زيادة لازمة لرقم البناء مع إعلانها وحفظ الأرشيف؛ لا تطلب اعتماد البناء نفسه مرة أخرى. لا يجيز ذلك تغيير إصدار المنتج أو الهوية أو التوقيع. إذا طلب المستخدم رقمًا بعينه وكان مؤرشفًا، بيّن التعارض ولا تستبدل الملف أو تغيّر الرقم خلاف طلبه.
- تحقّق من بيانات APK وتوقيعه وبصمته قبل تثبيت مصرح به. لا تلغِ التطبيق المثبت ولا تمسح بياناته لإجبار ترقية على النجاح.
- إذن البناء لا يجيز التثبيت أو النشر. وطلب تثبيت نسخة موجودة لا يجيز بناء نسخة غير موجودة دون أمر كتابي بالبناء.

عند طلب رفع GitHub صراحة:

- راجع الفروق والفرع وحالة remote والملفات المحلية، وارفع ما شمله الطلب فقط؛ لا تضم تغييرات سابقة غير مرتبطة.
- مسار Deploy اليدوي يبني وينشر إصدارًا؛ لا تُشغّله عند طلب push للمصدر.
- النتائج المحلية لا تعني نجاح CI. إن طلب المستخدم تشخيص فحوص PR الفاشلة، اقرأ gh-fix-ci واعتمد خطة الإصلاح وفق تفويضه؛ لا تشغّلها لمجرد وجود ملاحظات محفوظة.
